# Next no-learning step: explicit native kickoff reset compatibility test

The cold-contact-cache input difference has a measured large causal effect in
the unchanged simulator policy. Do not repeat this completed diagnosis or infer
that more PPO is the immediate remedy. No new training is specified here.

Implement a **separate versioned research packet runtime**, not an unannounced
edit to the published V1 runtime or an overwrite of the installed legacy bot.
Test the following narrow compatibility hypothesis on exact reference600:

1. On the first actionable policy decision of an actual native kickoff reset,
   supply the simulator's documented empty-cache representation (zero) for its
   eight individual-wheel observation fields. This is a **simulator-domain
   reconstruction for unavailable native fields**, not a claim that the car's
   wheels physically lost contact. Preserve `on_ground` and every other input.
2. Keep those fields explicitly unavailable/approximate in the capture mask and
   record a per-decision reset-projection flag. Do not promote their quality.
3. Apply the projection once per kickoff, never on ordinary pauses, duplicate
   packets, each four-tick decision, or arbitrary midplay rebinding. Define and
   test the actual lifecycle predicate before launch. All later wheel proxies,
   action-table mapping, recurrent state, held controls and cadence stay V1.
4. No scripted controller prefix, sampling change, additional feature masking,
   weights, rewards, physics, training, or checkpoint selection. This tests an
   observation compatibility hypothesis, not a policy repair by controller code.
5. Verify tests for first/reset-only application, byte-identical other fields,
   unchanged ordinary play/pause semantics, and immutable source/export hashes.
   Publish implementation plus the separate bounded native comparison authority
   before launch. Do not mutate/extend the expired V1 campaign.
6. Use a new external run directory. Compare the exact same checkpoint against
   the same native Nexto, on both teams, with normal game rules. Freeze time

   first decisions, consumed-control evidence, full outcome and touch/activity

A positive native result would support reset-domain alignment as a useful
compatibility correction. It would not prove SSL, general wheel observability,
complete simulator physics fidelity or that finishing650 is better. A negative
result must be preserved without retroactive reward/observation retuning.
