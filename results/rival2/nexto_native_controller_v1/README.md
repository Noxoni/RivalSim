# Native-v5 Nexto controller correction V1

This is an **opt-in opponent implementation**, not a new policy or training run.
Legacy code/results stay intact for reproduction. Older simulator scores do not
establish competence against native Nexto; see the benchmark correction notice.

## Implementation boundary

`third_party/nexto/native_v5.py` separates pending neural actions from emitted
controls, schedules each active world independently, uses the source-correct
168-tick kickoff table, and saves/restores controller state plus its own RNG.
The Nexto observation previous-action input is the pending action, as in the
native implementation, not the most recently emitted controls.

Choose a mode explicitly:

- `native_v5`: ordinary beta=1 argmax; kickoff beta=0.5 categorical sampling.
- `deterministic_argmax`: deterministic diagnostic variant, **not** native
  stochastic kickoff behavior. The prior causal comparisons used this variant.

An inactive world does not advance the virtual controller. `activate(mask)`
starts fresh virtual episodes for just those worlds. `notify_kickoff(mask)`
resets script admission only, retaining pending controls and neural cadence.
Every active call represents exactly one delivered 120 Hz physics tick.

`rivalsim/direct_skills_native_nexto.py` provides a separately named collector.
It inherits existing rewards, scenario bank, recurrent collection and learner
masking unchanged: half the worlds use self-play, half use Nexto; exactly one
third of trainable samples face inference-only Nexto. It does not modify old
runner defaults or turn an old checkpoint into a corrected campaign.

Save with `collector.opponent_checkpoint_state()`. Full adapter restoration
requires the matching physical world state and assignments. A campaign that
restarts physical episodes must explicitly call
`restore_opponent_for_fresh_episodes(state)` instead: RNG lineage is restored,
old action/clock caches are discarded, and new sides follow the fresh scenario.
That operation is **not exact physical-world continuation**. The old four-field
Nexto cache cannot represent the corrected controller and is rejected.

## Evidence and limits

`oracle.json` binds the installed executable and public source revision.
`oracle.npz` was generated by calling the actual installed `get_output`,
`maybe_do_kickoff`, `update_controls` and action-table methods on 512 packet
steps across eight independently active worlds. Its neural actions are fixed
substitutes; it validates the controller, not native neural/physics parity.
The actual global kickoff literal is source-bound too, avoiding the old copied
reference-table error. CPU tests additionally check categorical sampling, RNG
restoration, nonfinite rejection and explicit fresh-episode collector resume.

The first CPU fixture used NumPy's Windows int32 side indices and failed four
tests. The fixture now supplies the required int64 indices. Production's input
validation was not weakened. Both initial and corrected XML evidence remain.

`gpu_protocol.json` prospectively binds bounded GPU checks and all relevant
implementation sources before execution. It requires a CUDA oracle replay,
real-model replay with both sampling modes, a ten-world 20-second integration
smoke, and one 90-decision/32,768-world collector rollout. No optimizer is
constructed and no backward call or policy update is permitted. Results will
be recorded separately; CPU success alone is not GPU/integration success.

This correction does not prove all Nexto observations or RivalSim physics equal
Rocket League. Native countdown timing is not fabricated; inactive simulated
worlds use per-world virtual tick clocks. The existing collector infers kickoff
from a centered ball, whereas match evaluation uses match phase. CUDA RNG is
repeatable on the same device/runtime, not samplewise equal to native CPU RNG.
Native Rival scores remain 0-24 and 1-30; no capability promotion is made here.

## Reproduction

CPU: `.venv/Scripts/python.exe -B -m pytest -q tests/test_nexto_native_v5.py`.

GPU: `.venv/Scripts/python.exe -B benchmarks/validate_nexto_native_v5_gpu.py run`.
The committed bounded run refuses to overwrite/repeat an existing start receipt.
Do not delete evidence to bypass that guard. A recovery needs an explicit record.

No learning may use this module until its focused validation and the corrected
campaign's checkpoint/configuration are prospectively recorded. Shooting already
occupies 20% of the current direct-skills scenario starts; no scenario or reward
change was necessary for this controller correction.
